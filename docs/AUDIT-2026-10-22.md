# Repository audit and modernization — October 22, 2026

## Scope and product intent

Repository: `Legatto2/search.0t.rocks`. Starting commit: `4c71edd10e727fbcfd98920bd54d3d1258673e6f` on `main`. The audit covered the application, browser templates, dependency graph, deployment/bootstrap scripts, sample-data handling, and available GitHub configuration. No live customer service was modified or queried.

The owner clarified the intended product as a paid breach-intelligence service for vetted cybersecurity analysts, professional investigators, and law enforcement. The implementation is a private single-operator maintenance preview. The [product plan](PRODUCT.md) defines the additional identity, authorization, data, evidence, and billing controls required for the intended service.

The owner explicitly requested keeping and testing the inherited 75,739-record `sample.jsonl`. It remains byte-for-byte unchanged. Default CI uses two new fictional records. The separate opt-in corpus workflow performs isolated full-dataset validation and reports aggregates only; it does not establish the inherited dataset's provenance or redistribution rights.

Real-engine testing caught a Solr 9.11 behavior that mocks would miss: unauthenticated Configsets CREATE cannot clone the trusted default configset. Bootstrap now uses the supported Collections CREATE path, resulting in a dedicated `.AUTOCREATED` configset. No backend security setting was weakened to make that test pass.

The workflow auditor generated a safe patch proposal during the audit; its suggestions were reviewed and implemented in repository context. No blind automatic patch was applied.

## GitHub findings and limits

At the audit start, there were no open PRs, no open issues, and no workflow run history. Issues was disabled. The repository ruleset collection returned an empty list. Reading legacy branch protection returned HTTP 403 (`Resource not accessible by integration`), so legacy protection status is **unknown**, not proven absent.

No GitHub administrative settings, deployments, release publications, or merges were performed as part of the audit. The workflow files, update policy, issue form, and CODEOWNERS do not themselves enforce branch protection or enable private vulnerability reporting. The owner must confirm a working private reporting channel before public release.

## Important remaining work

1. Replace shared operator access with individual MFA, vetted organizations, case scope, field permissions, revocation, and audit trails before shared paid access.
2. Build a transactional account/entitlement/usage system and verified billing-event workflow; do not revive the legacy wallet callback.
3. Establish provenance, ingestion validation, retention, deletion/correction, and a controlled evidence-export design. Disabling automatic schema creation does not remove all inherited dynamic-field patterns.
4. Add backend credentials/authorization, encryption and recovery controls, representative capacity tests, and a rehearsed migration to the current Solr 10 major.
5. Confirm remote CI and actual repository protection/reporting settings. The single-host Solr/ZooKeeper topology has persistence, not high availability.
