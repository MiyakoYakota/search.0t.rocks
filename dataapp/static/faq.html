OPERATOR GUIDE

Search with confidence.

Breach intelligence for authorized cybersecurity analysts, professional investigators, and law-enforcement users.

Sign in

For a browser login, use operator as the username and your configured API token as the password. API clients use the Authorization: Bearer header. Tokens in URLs and user-agent strings are not supported.

Build a query

Enter one or more values on the search page. Different fields are combined with AND. Repeating a field in the API combines its values with OR. Prefix a field with not to exclude values, but include at least one positive search field.

Values are literal phrases interpreted by the configured field analyzer. Email and domain fields match complete identifiers without case sensitivity in the new schema. Usernames match their exact stored case. Other text fields can be case-insensitive and tokenized; string fields use their stored representation. This does not promise byte-for-byte equality. Wildcards and raw Solr query syntax are not supported.

Read results

HTML search returns a bounded list. Add wt=json for JSON. Use rows and start for bounded pagination. The supported API contract and limits are documented in the repository.

What data is included?

Only a synthetic fixture is supplied. The operator must provide and maintain any other dataset. The application does not scrape, buy, enrich, or connect to a public people-search database.

What changed?

Legacy wallet, payment, bulk export, and automated relationship expansion endpoints are unavailable in this preview. The paid professional service requires new account, scope, billing, and audit controls. The inherited implementations were incomplete and unsafe to expose. External map layers and browser CDN dependencies have been removed.

Remove or correct a record

Contact the operator of this particular instance. The software repository does not control the operator's collection. Operators must establish a clear contact and retention process before accepting real data.
